# Фоновая подкачка права

`scripts/background_corpus.py` обслуживает нормативные источники в отдельном
процессе. Themiz читает последнюю рабочую копию и не ждёт завершения загрузки.
Неполный кандидат не заменяет файл, ошибка одного акта не останавливает очередь.

## Что входит

Базовый реестр включает 17 действующих записей сборщика: кодексы, ЗоЗПП и
используемые федеральные законы. НК представлен главой 25.3, а не всем кодексом.
Существующие Пленумы ставятся в очередь каждый отдельно. Каталог служит для
обнаружения дополнений; его недоступность не блокирует уже известные акты.

Дополнительные ФЗ и подзаконные акты перечисляются в `config/corpus-needs.json`.
У записи должны быть точный публичный адрес, вид акта, название, дата и номер.
Регистрация означает потребность, а не подтверждение свежести. Поддерживаемый
парсер проверяет полный текст и реквизиты; неизвестная верстка или закрытый
документ дают причину отказа. Список не пополняется догадками или сканированием
материалов всех дел.

Обзоры судебной практики можно зарегистрировать как потребность, но их новая
ветка загрузки пока закрыта: `review_parser_not_verified`. Проверка выявила,
что первоначальный парсер мог принять CAPTCHA за текст обзора. До отдельной
приёмки HTML/PDF-парсера загрузка обзоров не начинается, остальные виды актов
продолжают обслуживаться.

## Работа

```sh
python3 scripts/background_corpus.py --status
python3 scripts/background_corpus.py --enqueue-all
python3 scripts/background_corpus.py --enqueue legal-corpus:code:gpk-rf
python3 scripts/background_corpus.py --enqueue legal-corpus:code:gpk-rf --force
python3 scripts/background_corpus.py --enqueue-all --force
python3 scripts/background_corpus.py --schedule
python3 scripts/cite.py --json "ст. 131 ГПК"
```

При включённом фоне цитатор ставит известный недостающий или сомнительный
источник в локальную очередь. Это не сетевой запрос. Если очередь занята или
повреждена, найденный текст остаётся доступен; ошибка фонового слоя показана
отдельно. Коды цитатора сохранены: 1 — не найдено, 2 — требуется сверка,
3 — нарушение целостности. Фоновый режим не отменяет юридический допуск.

Обычная постановка сохраняет паузы повторов и причины блокировки. Явный
`--force` запрашивает новый повтор, но не отменяет запреты источника и проверки
кандидата. `cite.py --enqueue` также означает явный повтор указанного источника.

`--force` повторно ставит выбранные зарегистрированные ресурсы до истечения
недельного окна. Одинаковые постановки идемпотентны; работающий ресурс получает
pending-версию и не прерывается. `--schedule` возвращает интервал запуска и
сводку очереди для локального интерфейса. Эти операции не зависят от подписки.

Дополнительный акт регистрируется локально:

```sh
python3 scripts/corpus_registry.py --add --kind bylaw \
  --slug example-act --source 'https://www.consultant.ru/document/cons_doc_LAW_ID/' \
  --title 'ТОЧНОЕ НАЗВАНИЕ' --date ДД.ММ.ГГГГ --number НОМЕР
```

Это шаблон, не настоящий источник. Для ФЗ используется `--kind federal-law`.
Сначала сверяют реквизиты по публичному источнику, затем добавляют запись и
ставят возвращённый id в очередь. Для чтения скачанного акта:
`python3 scripts/cite.py --resource ID --json` (с `--full` для полного текста).

Для обзоров ВС РФ используется тот же реестр и receipt Линкея. Добавлять обзор
можно только после проверки точного публичного URL и реквизитов через
`add_review(...)`; закрытый или неполный ответ не заменяет рабочую копию. В
конфиг намеренно не внесён вымышленный обзор.

## Фон и ограничения

### Предварительное условие

Фоновая подкачка требует локальный Lynceuz и Node 20+. Они не ставятся этим
репозиторием автоматически. Следуйте официальному README:

```sh
git clone https://github.com/zarubinvibe/lynceuz.git
cd lynceuz
node scripts/onboard.mjs
```

Если Lynceuz установлен вне стандартного каталога, задайте `LYNCEUZ_HOME`
(корень его репозитория). Без Lynceuz локальное чтение и уже загруженный корпус
работают, но фоновую подкачку нельзя считать готовой.

Устанавливается только из канонической копии Themiz:

```sh
python3 scripts/background_corpus.py --install
```

Задание `com.themiz.corpus-background` запускается раз в пять минут, с низким
приоритетом CPU/диска. Работает один загрузчик; запросы последовательные.
Порция ограничена временем, проверенные части сохраняются. После перезапуска
работа продолжается; отказ получает собственную паузу перед повтором.

Очередь и доказательства лежат в `.agent/maintenance/background/`, не в Git.
Рабочие акты остаются в `knowledge/kodeksy/`, `knowledge/plenumy/` и
`knowledge/akty/`. Новые байты проверяются до активации; прежние сохраняются.
Локальные правки не затираются обновлением. Отсутствующий или изменившийся
источник не получает новую успешную дату.

Линкей забирает только разрешённые публичные страницы. Ключи, клиентские
материалы и тексты дел в запросы не попадают. CAPTCHA, авторизация и платный
доступ не обходятся. Если источник закрыт, запись остаётся с причиной отказа,
а загрузчик занимается другими актами.

Подкачка выполняется без LLM и не ждёт сброса Codex. Обслуживание версий программ
и навыков остаётся в `weekly_maintenance.py`, с прежней проверкой недельного
сброса подписки. Денежных и произвольных токенных потолков нет.

Остановить только этот фон: `python3 scripts/background_corpus.py --uninstall`.
Очередь, доказательства и рабочие копии сохраняются. Для возобновления нужен
тот же `--install`. Общий Python, ОС и чужие задания не меняются.

## Отдельный Graphify права

После фоновой порции запускается независимая проверка графа. Первая сборка —
сразу; далее раз в семь дней по изменившимся рабочим копиям. Завершения всей
очереди ждать не нужно. Неизменившийся корпус не пересобирается. У графа своя
блокировка и предел фонового запуска 60 секунд; сбой не отменяет загрузку актов
и не закрывает последнюю рабочую версию поиска.

```sh
python3 scripts/legal_graph.py --status --json
python3 scripts/legal_graph.py --query 'статья 131 ГПК' --json
python3 scripts/legal_graph.py --refresh --force --json
```

Граф хранится отдельно в `.agent/maintenance/legal-graph/`, не попадает в Git
и не смешивается с `graphify-out/` графом программного кода. Источники — только
реестр нормативных актов; клиентских документов, вопросов и ответов там нет.
Узлы содержат источник, редакцию и хеш; дата построения не означает проверку
действующей нормы. Изменившийся после сборки источник помечается при поиске.
Полнотекстовый поиск идёт по локальному SQLite FTS5-индексу внутри снимка.
Старый формат снимка остаётся читаемым через JSON-fallback; при следующей
проверке он пересобирается с индексом. Источники и прежний снимок доступны
во время сборки. Замеры и границы приёмки — в
[отчёте](background-corpus-acceptance.ru.md).

Применяется локальная сборка Graphify из явно извлечённых статей, пунктов и
ссылок. Семантические догадки не добавляются. Сборка и поиск не вызывают LLM,
API или платный векторный сервис. Это адаптация режима Graphify для автономного
нормативного корпуса: стандартное обновление Markdown требует модельного
извлечения ([описание проекта](https://github.com/Graphify-Labs/graphify)).
Отчёт формируется без тяжёлой HTML-визуализации. Требуется установленный
`graphifyy`; при его отсутствии выводится причина, автоматической установки
в общий Python нет.
