# Первый запуск Themiz

<p align="center"><img src="assets/pantheon/workflow/01-intake.png" alt="Иллюстрация приема материалов Themiz, не снимок приложения" width="100%"></p>

Этот путь рассчитан на macOS, Python 3.11 или новее и Xcode Command Line Tools. Apple Vision распознает сканы только на Mac. Полная установка на Windows и Linux пока не проверена. Доступ к выбранному агенту и лимиты его подписки настраиваются отдельно.

Если удобнее разговор, открой [пошаговый онбординг](ONBOARDING-CHAT.ru.md) в Codex CLI или Claude Code. Оба клиента равноправны. Перед установкой попроси объяснить изменения на диске.

## Шаг 1: Проверь среду

```bash
sw_vers -productVersion
python3 --version
xcode-select -p
```

Первая команда покажет установленную версию macOS, вторая Python 3.11 или новее, третья путь к инструментам разработчика. Для расшифровки аудио также понадобятся ffmpeg и локальная модель Whisper. Если одного из компонентов нет, установщик назовет его в итоговом отчете. Не считай отказ или таймаут успешной проверкой.

## Шаг 2: Скачай проект

```bash
git clone https://github.com/zarubinvibe/themiz.git
cd themiz
```

После первой команды появится папка `themiz`. Вторая команда перенесет терминал в нее. Без Git скачай [ZIP](https://github.com/zarubinvibe/themiz/archive/refs/heads/main.zip), распакуй его и открой полученную папку в терминале.

## Шаг 3: Установи и включи окружение

```bash
bash install.sh
. .venv/bin/activate
```

Установщик положит пакеты Python в `.venv`, подготовит шрифт, локальные инструменты распознавания и рабочие каталоги. В конце он напечатает отчет. После второй команды приглашение терминала обычно начинается с `(.venv)`.

## Шаг 4: Выбери клиент

Codex CLI:

```bash
codex
```

Попроси настроить Themiz по скиллу `themiz-setup`.

Claude Code:

```bash
claude
```

Затем запусти `/themiz-setup`. В обоих клиентах агент должен прочитать правила проекта, уточнить твою практику и объяснить нужные доступы до работы с материалами доверителя. Оба пути ведут к одной настройке проекта.

## Шаг 5: Проверь границы на безопасном примере

Начни с копии файла без чувствительных данных. Извлечение текста и OCR выполняются локально. Фрагменты, переданные агенту, обрабатывает выбранный поставщик модели. До настоящего дела попроси агента назвать эту границу своими словами. Исходники в `00_intake/` после приема не меняй.

Публичный клон не содержит готового нормативного корпуса. Разрешенные источники и нужные документы настраиваются отдельно. Если загрузка не удалась или редакция не подтверждена, вопрос остается открытым. Текст на диске сам по себе не доказывает актуальность нормы.

## Шаг 6: Прочитай состояние дела

Сначала создай дело с агентом. Вместо `cases/client/case` подставь фактический путь существующей папки дела. Эта команда дает сводку конкретного дела, а не общий обзор состояния программы.

```bash
python3 scripts/themiz_status.py cases/client/case --brief
```

Проверь карту фактов по исходникам: суммы, номера дел и цитаты требуют сверки. Для узкой задачи используется FAST, для сложной используется FULL с отдельными читателями и рецензией. Черновик проверяет роль, которая его не писала. Подписывать и подавать документ решаешь ты.

## Шаг 7: При желании открой браузерную панель

```bash
.venv/bin/python cockpit/app.py
```

Открой `http://127.0.0.1:8800`. Появится локальная панель состояния. Она необязательна, а ее агентные кнопки пока вызывают только Claude Code. Для задач через Codex используй Codex CLI.

## Шаг 8: Обнови существующий Git-клон

В Codex попроси обновить Themiz по скиллу `themiz-update`. В Claude Code запусти `/themiz-update`. Для такого обновления нужен Git-клон. Если проект установлен из ZIP, создай свежий Git-клон; после проверки перенеси локальные данные с агентом и не перезаписывай исходники. Сначала проверь предложенные изменения и состояние рабочей папки. Обновление программы и проверка редакций законодательства остаются разными операциями.

Пригодилось? [Поставь звезду](https://github.com/zarubinvibe/themiz). Нашел ошибку? [Открой issue](https://github.com/zarubinvibe/themiz/issues), приложи команду, сообщение об ошибке и вымышленный пример. Материалы доверителей не публикуй.

Хочешь внести исправление: сделай fork, создай ветку branch, оформи commit, отправь push и открой Pull Request. Не отправляй изменения прямо в `main`.
