## Промт исполнителя
ЕДИНСТВЕННЫЙ КРАСНЫЙ СЕЛФТЕСТ В СИСТЕМЕ. Прогон всех 61 селфтестов 01.09.2026: зеленых 60,
красный один - этот. И он врет в ОБЕ стороны.

Как краснеет сейчас:

    AssertionError: рабочие сторожа не признаны:
    [('hooks:hookspath', 'core.hooksPath уводит хуки вне репозитория (~/.agents/git-hooks) —
      файлы на месте, но git зовет не их'), ('hooks:empty-commit-msg', ...)]

ЭТО ДВОЙНАЯ ОШИБКА, И ОБЕ НАДО ЧИНИТЬ.

1) ФИКСТУРА НЕГЕРМЕТИЧНА. Селфтест строит временный репозиторий, но не изолирует его от
   ГЛОБАЛЬНОГО конфига git. На машине владельца core.hooksPath задан глобально, и временный
   репозиторий его наследует. Проба меряет настройку машины, а не прибор. Это третий повтор
   одного и того же урока: фикстура строится ПО ТУ СТОРОНУ проверяемого порога.

2) ДИАГНОЗ ЛОЖЕН ПО СУЩЕСТВУ. Проверено на живом доме сегодня: глобальные хуки в ~/.agents/git-hooks
   ЗОВУТ приборы репозитория через git rev-parse --show-toplevel. Цепочка защиты персональных
   данных ЖИВА целиком:
     pre-commit  -> pd_guard --staged
     commit-msg  -> entire -> commit-msg.pre-entire -> pd_guard
     pre-push    -> entire -> public-repo-gate -> pre-push.pre-public-repo-gate.user -> pd_guard --push
   То есть прибор объявляет мертвой работающую защиту. Ложная тревога у сторожа хуже молчания:
   такой сторож снимают в первый день.

Известны еще два дефекта того же прибора, оба из разбора:
  - `exec /bin/true # pd_guard.py` считается живым хуком: прибор судит по УПОМИНАНИЮ имени
    в тексте, а не по тому, что хук делает;
  - `_matcher_covers("Write")` дает истину при покрытии одной двери из четырех.

СДЕЛАЙ:
1) Герметизируй селфтест: временный репозиторий с ЯВНО заданным своим core.hooksPath и с
   очищенным влиянием глобального и системного конфига. Проба обязана давать один и тот же
   ответ на машине владельца и на чистой машине.
2) Суди хук по ФАКТИЧЕСКОМУ ЗАПУСКУ, а не по наличию файла и не по упоминанию имени: подай
   хуку вход и проверь, что прибор был позван и вернул ожидаемое. Цепочка через chained-хуки
   обязана признаваться живой - сегодня она признается мертвой.
3) Покрытие матчера считай по МНОЖЕСТВУ инструментов, а не по одному: покрытие одной двери
   из четырех - это не покрытие.
4) После починки прогони на живом доме и убедись, что прибор говорит правду: цепочка ПД жива,
   хотя хуки лежат вне репозитория.

ВТОРОЙ КРУГ, И СНАЧАЛА ПРЕДУПРЕЖДЕНИЕ. Первый круг сломал машину владельца. Враждебная проба
делала «git init» во временном каталоге, а у владельца core.hooksPath задан ГЛОБАЛЬНО на
~/.agents/git-hooks. Что-то в прогоне позвало установку хуков, и четыре общемашинных хука были
перезаписаны шаблоном без проверки существования прибора. После этого коммит в ЛЮБОМ репозитории
без scripts/pd_guard.py падал с кодом 128 «ref updates aborted by hook». Починено руками, прежние
версии сохранены рядом с суффиксом .slomannyy-2026-09-02, отдельная задача R10 чинит установщик.

ИЗ ЭТОГО ТВОЕ ЖЕСТКОЕ ОГРАНИЧЕНИЕ: ни селфтест, ни любая твоя проба НЕ ИМЕЮТ ПРАВА писать за
пределы дома миссии. Временный репозиторий заводи только со СВОИМ core.hooksPath и с
GIT_CONFIG_GLOBAL=/dev/null, чтобы он не унаследовал настройку машины. Проверь это ГРЕПОМ по
своему же коду перед сдачей: ни одной записи в $HOME, ни одного вызова установки хуков.

НЕ ОСЛАБЛЯЙ проверку: если цепочка действительно разорвана, прибор обязан краснеть.
