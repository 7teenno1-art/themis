## Промт исполнителя
Три дефекта в одном приборе, все три видны только в коде.

1) ЛИТЕРАЛ ИМЕНИ ПАПКИ. На строке 40 корень проекта вычислен правильно:

       PROJECT_ROOT = os.path.dirname(os.path.dirname(os.path.realpath(__file__)))

   А на строках 1417 и 1586 сторож судит по литералу:

       and re.search(r"/themiz/", p_res.replace("\\", "/"), re.I)
       if cwd and "themiz" not in cwd:

   Переименуй папку - и сторож ослепнет молча. Селфтест дефект не видит, потому что САМ создает
   временный каталог с «/themiz» в имени (строка 1599). Это фикстура по эту сторону порога.

2) МЕРТВАЯ КОНЪЮНКЦИЯ. Строка 1368:

       if tool in ("WebFetch", "WebSearch") and tool == "WebFetch":

   Условие сводится к tool == "WebFetch". Ветка WebSearch недостижима. Даже когда матчер хука
   будет подписан на WebSearch, сторож ее пропустит. У WebSearch нет поля url - у него query,
   поэтому проверка хоста ему не подходит, и правило для него нужно другое.

3) СЕЛФТЕСТ НЕГЕРМЕТИЧЕН. Строки 1599 и 1610 строят фикстуры, зависящие от имени каталога.

СДЕЛАЙ:
1) Замени оба литерала на сравнение с PROJECT_ROOT через os.path.realpath. Сравнение путей на
   macOS ВСЕГДА через realpath: /var - симлинк на /private/var, и наивное сравнение молча делает
   прибор пустышкой с кодом 0. Этот урок уже стоил конвейеру одного прогона.
2) Почини конъюнкцию. Для WebFetch правило остается прежним - проверка хоста по белому списку.
   Для WebSearch правило другое: пока в этом прогоне не было вызова scripts/practice_search.py,
   WebSearch по ПРАВОВОМУ запросу блокируется с текстом, называющим прибор. Признак прохождения
   лестницы бери детерминированно с диска (кеш practice_search), не из памяти модели. Признак
   «правовой запрос» - словарь в коде, не догадка.
3) Перепиши селфтест: гоняй его во временном каталоге с ПОСТОРОННИМ именем. Добавь проверку,
   которая краснеет, если в файле снова появится литерал имени проекта в логике поиска корня.

ВТОРОЙ КРУГ. Первый круг закрыл литерал и конъюнкцию, селфтест дал 139/139, но проверяющий
нашел ДВЕ дыры, и обе настоящие. Гейт остался открытым в живом доме.

ДЫРА ПЕРВАЯ, ГЛАВНАЯ. scripts/claude_guard.py:1272 считает лестницу поиска пройденной, если в
каталоге {корень}/.cache/practice лежит ХОТЬ ОДИН json. На этой машине их 2787, самые свежие от
17.08.2026. Значит признак «practice_search уже звали» истинен ВСЕГДА, и блок WebSearch не
срабатывает никогда. Замерено проверяющим дословно:

    practice_search_used= True
    json_count= 2787

Признак обязан быть ПРО ТЕКУЩИЙ ПРОГОН, а не про существование каталога. Свежесть определяй
детерминированно с диска: отметка времени старта прогона, либо запись в файле прогона, либо
попадание кеша моложе старта сессии. Способ выбери сам, но условие одно: вчерашний кеш НЕ
открывает сегодняшний WebSearch. Проверять это надо В ЖИВОМ ДОМЕ, а не во временном каталоге:
временный каталог без кеша даст зеленый на неисправном стороже - это фикстура по эту сторону порога.

ДЫРА ВТОРАЯ. Анти-регрессная проверка на scripts/claude_guard.py:2136 ищет имя НОВОГО каталога.
Проверяющий подставил корень «postoronnee-r05», вернул литерал «themiz» в логику поиска корня и
получил detected= []. Защита от повтора дефекта сама не срабатывает. Она обязана ловить ЛЮБОЙ
литерал имени каталога в логике поиска корня, а не сверять с одним ожидаемым именем.

ТРЕТЬЕ, СПРАВОЧНО, ЧИНИТЬ НЕ НАДО. Проверяющий не смог выполнить check_cmd: mktemp в его песочнице
отдает Operation not permitted, селфтест упал на «No usable temporary directory found»
(scripts/claude_guard.py:1666). Права на временный каталог есть у гейта, а не у проверяющего.
Если селфтест может обойтись без mktemp - сделай, это удешевит проверку. Если нет - оставь.

НЕ РАСШИРЯЙ здесь матчер хука в .claude/settings.json - это отдельная задача, и файл там чужой.
НЕ ОСЛАБЛЯЙ ни одну существующую блокировку.

## Промт проверяющего
ВЕРДИКТ: зеленый|красный
Отчет исполнителя не читай. Проверяй по диску. Запусти check_cmd и probe_cmd. Проба обязана краснеть на состоянии ДО исправления и зеленеть после. При красном назови точный путь и условие.

Отдельно проверь:
(а) В ЖИВОМ ДОМЕ, не во временном каталоге: событие WebSearch с правовым запросом обязано
    дать ненулевой код ПРИ СУЩЕСТВУЮЩЕМ каталоге .cache/practice со старыми файлами. Это
    главная проверка задачи: временный каталог без кеша зеленеет и на сломанном стороже;
(а2) верни литерал имени каталога в логику поиска корня во ВРЕМЕННОЙ КОПИИ файла и убедись,
    что анти-регрессная проверка его ЛОВИТ - при корне с любым посторонним именем;
(б) событие WebSearch с правовым запросом дает ненулевой код, а с явно служебным запросом - нулевой;
(в) событие WebFetch по-прежнему судится по белому списку хостов и ничего не потеряло;
(г) в логике поиска корня проекта не осталось литерала имени папки - грепом;
(д) селфтест краснеет, если вернуть литерал обратно;
(е) НИ ОДНА старая блокировка не ослаблена: прогони весь селфтест целиком и сверь число проверок
    с тем, что было до задачи.
