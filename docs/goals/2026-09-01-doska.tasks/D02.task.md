## Промт исполнителя
Сторож не защищает сам себя, и это проверено пробой 01.09.2026:

    Write в scripts/claude_guard.py   -> код 0
    Write в .claude/settings.json     -> код 0
    rm scripts/claude_guard.py        -> код 0

Закрывать это ОДНИМ сторожем нельзя: это круг. Сторож не может пережить собственное удаление,
и правило, живущее внутри удаляемого файла, не правило. Конституция владельца требует дословно:
«Безопасность (жестко, не текстом): settings.json permissions.deny + hooks/security-guard.sh» -
то есть deny ПЛЮС хук, а не хук вместо deny.

Сегодня в .claude/settings.json ровно одна запись deny, и она посторонняя:
    "deny": ["Read(./.entire/metadata/**)"]

СТОЛКНОВЕНИЕ С СОСЕДНЕЙ ЗАДАЧЕЙ, ЧИТАЙ ВНИМАТЕЛЬНО. Прошлый круг ты добавил проверку версии
Claude Code внутрь --selftest. Час назад задача R11 специально увела ВСЕ проверки окружения из
--selftest в отдельный флаг --runtime, и вот почему: --selftest сторожа служит check_cmd сразу
нескольким задачам, и старая версия харнесса роняла их все, выдавая «у тебя старая машина» за
«твой код сломан». Это тот же грех, что уже вычищен в приборе бюджета.

ПРОВЕРКА ВЕРСИИ УЖЕ ЕСТЬ и работает: python3 scripts/claude_guard.py --runtime отдает код 1 и
называет «Claude Code 2.1.207 < 2.1.228». Второй раз ее заводить НЕ НАДО и в --selftest класть
НЕЛЬЗЯ. Если тебе нужно, чтобы жесткость слоя зависела от версии, - выражай это в --runtime.

--selftest судит ТОЛЬКО код: подписку матчера, содержимое deny, попадание шаблонов. На исправном
коде он зеленый при любой версии харнесса.

СДЕЛАЙ:
1) Заполни permissions.deny так, чтобы правка и удаление сторожа, файла настроек и приборов
   приемки были закрыты жестким слоем харнесса, а не советом. Перечень приборов приемки собери
   с диска, а не по памяти: те, что зовет гейт и приемка.
2) Оставь законный путь изменения: правка настроек и сторожа возможна, но не из сессии, которая
   ведет дело. Признак «ведет дело» бери детерминированно с диска.
3) В --selftest сторожа добавь проверку, которая читает .claude/settings.json и краснеет, если:
   deny пуст либо не содержит самозащиты; множество инструментов матчера PreToolUse разошлось
   с множеством инструментов, которые сторож реально обрабатывает в main().
   Сегодня матчер равен Read|Write|Edit|NotebookEdit|Bash, а рядом стоит ОТДЕЛЬНЫЙ PreToolUse
   с матчером Agent, занятый хуком Entire. Учти это: два хука на одном матчере уживаются, и надо
   решить и записать в коде, что происходит при коде 2 у нашего сторожа.
4) НЕ СНИМАЙ ни одного инструмента с матчера. Расширение допустимо, сужение запрещено.

НЕ ТРОГАЙ хуки Entire: отслеживание сессий обязательно и отключать его нельзя.

## Промт проверяющего
ВЕРДИКТ: зеленый|красный
Отчет исполнителя не читай. Твоя песочница ТОЛЬКО ДЛЯ ЧТЕНИЯ: временный каталог тебе
не создать. check_cmd и probe_cmd гоняет ГЕЙТ, а не ты - враждебная проба строит сломанный
вход и потому принадлежит гейту. Не пытайся их запускать: красный на «mktemp: Operation not
permitted» будет ложным, а от ложных красных судью перестают читать.
Проверяй утверждения ниже своими средствами: чтением кода, грепом, запуском того, что
записи не требует. Сомнение трактуй в красную сторону. При красном назови точный путь и условие.

Отдельно проверь:
(а) permissions.deny содержит самозащиту сторожа и файла настроек;
(б) попытка записи в scripts/claude_guard.py из сессии, ведущей дело, отбивается;
(в) законная правка вне работы по делу по-прежнему возможна;
(г) хуки Entire на месте и не тронуты;
(д) селфтест краснеет, если очистить deny;
(д2) в --selftest НЕТ ни одной проверки версии харнесса или иного окружения - грепом.
     Окружение судит только --runtime;
(е) ни один инструмент не снят с матчера PreToolUse - сверь список до и после.
