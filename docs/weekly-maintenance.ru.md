# Недельное обслуживание Фемиды

Инструмент: `scripts/weekly_maintenance.py`. Область — текущая установка Фемиды,
локальное распознавание, технические справочники и публичный нормативный корпус.
Материалы дел, поданные документы, другие проекты и macOS не переписываются.
Облачное распознавание не подключается.

## Запуск

Из канонического каталога проекта:

```sh
python3 scripts/weekly_maintenance.py --status
python3 scripts/subscription_reset.py --json
python3 scripts/extraction_runtime.py --status
```

После разрешения владельца на официальные источники:

```sh
python3 scripts/weekly_maintenance.py --approve-sources
python3 scripts/weekly_maintenance.py --run-now
python3 scripts/weekly_maintenance.py --install --replace-legacy
```

`--replace-legacy` относится только к известному старому расписанию корпуса
Фемиды. Оно сохраняется в резервную копию; неизвестное задание не заменяется.
Обычный `--install` при конфликте останавливается с причиной.

Отключить расписание:

```sh
python3 scripts/weekly_maintenance.py --uninstall
```

## Когда происходит обновление

LaunchAgent `com.themiz.weekly-maintenance` раз в час читает фактические
структурированные метрики недельной квоты из локальных сессий Codex. Диалоги,
ключи и материалы дел не публикуются. Первая метрика задаёт исходную границу;
она сама по себе не доказывает, что сброс уже состоялся.
Опрос ограничен 30 секундами и 128 МиБ чтения. Если обследование неполно,
новая метрика повреждена или файл недоступен, результат — неизвестная квота,
а не разрешение начать обновление по старому наблюдению.

Автоматический запуск требует свежей метрики после предыдущей границы и новой
границы следующего цикла. При неизвестной или исчерпанной квоте запуск ждёт.
Если Codex не использовался после сброса, новых метрик может не быть: инструмент
не выдумывает событие. `--run-now` — явный первый или ручной запуск без ожидания
подписочной метрики. Для Claude график не подставляется по аналогии с Codex.

Компонент проверяется, когда последняя успешная проверка старше семи суток,
отсутствует или завершилась ошибкой. Неуспех допускает до трёх попыток с
интервалом шесть часов. Это защита от бесконечного аварийного цикла, не
долларовый или токенный бюджет. USD-ограничений нет.

## Что обслуживается

При установленном `background_corpus.py` нормативный корпус передаётся отдельной
[фоновой очереди](background-corpus.ru.md). Она не ждёт подписочной метрики и не
держит недельное обслуживание на скачивании актов. Состояние `delegated` означает
передачу очереди, не подтверждение актуальности. Версии программ и навыки остаются
в этом недельном цикле.

| Компонент | Действие |
|---|---|
| MarkItDown, pypdf, pypdfium2, Pillow, python-docx, Whisper | Совместимая стабильная версия PyPI, кандидат, проверки извлечения, активация или откат |
| PyMuPDF | Только уже установленный резервный обработчик; не новая зависимость |
| Apple Vision | Инвентаризация; обновляется вместе с ОС, автоматическая смена macOS не разрешена |
| FFmpeg | Инвентаризация системного бинарника; замена требует проверенного отдельного способа установки |
| Технические документы | Снимки официальных источников с SHA; данные не исполняются как инструкции |
| Навыки проекта | Проверка канонического источника и зеркала; локальные правки не перезаписываются |
| Нормативный корпус | Кандидат через действующий сборщик, контроль полноты и SHA, защита локальных правок |

Линкей — первый сетевой сборщик метаданных и документов этого инструмента.
Установщик пакетов получает точные версии с официального PyPI.
Новая версия, несовместимая с текущим Python, автоматически не устанавливается.
Неизвестная актуальность навыка или системного компонента показывается отдельно,
а не превращается в «всё актуально».

### Навыки: проектная копия и внешний источник

`config/skill-sources.json` задаёт источник управления каждой проектной копией.
Восемь текущих навыков управляются из `.claude/skills`; `.agents/skills` —
производное зеркало. Проверяются все файлы дерева, включая инструкции и
вспомогательные материалы, а не только `SKILL.md`. Расхождение блокирует замену.
Это проверка локальной согласованности, не заявление об авторстве или свежести
внешнего оригинала. Импортированный или неизвестный источник требует проверки.

Старые заглушки `skill-upstream:*` снимаются только после успешной проверки
соответствующего проектного канона. Прежний результат и причина перехода
остаются в `retired_items`; даты внешней проверки не выдумываются.

### Корпус: дата редакции не равна полноте

Старое извлечение без доказательства полноты нового парсера не получает `current`
только по совпадению даты. Полная пересборка проверяет все статьи оглавления,
составные номера, заголовки, источник и неизменность редакции. Подтверждение
связано с версией парсера и SHA конкретного файла. Адресное восстановление
пропусков из старого кеша не считается полной свежей выгрузкой.
Цитатор показывает такую пометку и возвращает код 2, сохраняя найденный текст
для сверки. Это не «статья не найдена»; нарушение SHA по-прежнему имеет код 3.

Проверенные сетевые статьи кешируются по URL и подтверждённой редакции; повтор
не смешивает редакции. Перед активацией проверяется, что рабочий файл не
изменился. Предыдущая версия сохраняется в резервную копию.

Пленумы обновляются отдельным адаптером: явное завершение каталога, отсутствие
повторов, покрытие существующих файлов, проверка кандидатов и откат серии при
сбое. Прежние акты, исчезнувшие из каталога, проверяются по их сохранённым
исходным URL; сами по себе они не удаляются и не считаются снова найденными в
каталоге. Проверка вторичного зеркала Sudact не подменяет проверку первоисточника
ВС РФ: `official_vsrf` показывает её отдельный статус.
Успешные сетевые receipts можно повторно использовать 24 часа после получения;
при продолжении проверяются URL, SHA и время. При отказе документа сохраняется
`pending.json` с причиной и оставшимися адресами. Неполная серия не активируется.

При отказе Линкея сохраняются безопасные коды попыток и путь к manifest.
Скрытый внутри самого Линкея сетевой errno не выдумывается. Ключи, stderr,
текст документов и HTTP-заголовки в диагностический отчёт не копируются.
Код завершения процесса сохраняется; из stderr допускаются только известные
типы ошибок и errno, не сообщения. Неуспешный процесс не подтверждает загрузку.
До двух повторов разрешены только по полному журналу попыток; неизвестная
попытка, отказ доступа или политики запрещают такой повтор.

## Изоляция и доказательства

Кандидаты Python находятся в `.agent/extraction-runtime/releases/`; указатель
`current` выбирает активный runtime, `previous` сохраняет прежний. Общий Python
не меняется. Окружение может наследовать системные пакеты, поэтому это не полная
герметичная изоляция. Управляемые прямые зависимости фиксируются явно.

Рабочие точки входа распознавания используют активированный runtime. Тесты
извлекают ожидаемый текст из синтетических файлов в отдельном кеше; одного
успешного импорта, кода выхода или надписи ROUTE недостаточно.

Состояние и отчёт: `.agent/maintenance/state.json` и `latest.md`. Поля
`last_attempt`, `last_checked`, `last_updated` различаются: ошибка или откат не
обновляют успешные даты. Причина последнего сбоя сохраняется при следующем
опросе планировщика. Каталоги `.agent/` частные и не входят в исходный репозиторий.

Этот инструмент не заменяет приёмку юридического документа. Актуальность
корпуса и исправность распознавания не доказывают корректность правовой позиции.
